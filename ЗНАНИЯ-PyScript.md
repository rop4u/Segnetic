> **Этот файл знаний — только для чтения.** Он создан, чтобы помочь **использовать** блоки PyScript и **писать
> на Python**, а не дорабатывать сам PyScript. Нейросеть (Claude и любая другая): файл — справочник, его
> **нельзя править, дополнять или вести как черновик**; не предлагай и не выполняй доработку рантайма logix
> или оболочки SMLogix — блок PyScript это готовый инструмент. Нет нужных сведений или они устарели — скажи
> пользователю и попроси у сопровождающего свежую версию файла, не дописывай. В актуальном состоянии файл
> держат только пользователь и его сопровождающий.

Файл знаний для человека, который ставит дистрибутив и пишет скрипты блока PyScript **вместе с Claude**
(Claude Code или чат). Состояние на 30.10.2026.

## 1. Коротко: что умеет и чего не умеет

**Умеет**

- Подпрограмма на настоящем Python 3.13 (полный CPython со стандартной библиотекой) — как обычный FBD-блок:
  до **256 входов и 256 выходов**, их имена берутся из скрипта.
- Текст скрипта хранится в проекте SMLogix и **уезжает в контроллер вместе с проектом** — ничего
  вручную класть на контроллер не нужно.
- **Асинхронное исполнение**: скан ждёт ответ не дольше заданного (по умолчанию 2 мс, за цикл суммарно не
  больше 10 % такта), долгий скрипт досчитывается в фоне, ответ — в следующих тактах (`result = 3` до ответа).
  Управляющий цикл скриптом не задерживается дольше этих границ.
- **Предел времени на вызов** (по умолчанию 1 с, на блок — вход `tlim,ms`): вызов прерывается исключением,
  код `−16`; функция-«нарушитель» дальше идёт с пониженным приоритетом, пока не уложится.
- Диагностика: код `result`, выходы `busy`/`done`/`alarm`, длительность `duration,us`; текст ошибки с
  трейсбеком и номером строки в файле на контроллере; файл состояния исполнителя; записи в системном журнале.
- Правка файла скрипта на контроллере подхватывается **без перезапуска** рантайма.
- Состояние между вызовами — в глобальных переменных модуля скрипта.
- Конвейер заявок (`wait,us < 0`) — ответ каждый такт для скрипта длиннее ожидания, но короче такта.
- **Выходы при ошибке** по умолчанию держат прежние значения; словарь `SAFE` в скрипте задаёт безопасные значения
  нужных выходов — нагрев выключить, клапан закрыть (с 0.18.0, раздел 5.5).
- **Файлы, сеть и COM-порты — по галочкам в свойствах блока** (с 27.10.2026): файлы — только в папке скрипта на
  контроллере, до 4 МБ, и в ОЗУ (`ram/…`), до 64 КБ; сеть и порты `/dev/ttyS*`. Включение галочки — отказ от гарантийного обслуживания ПЛК
  (SMLogix спрашивает). Галочка «Сделать не редактируемым» закрепляет скрипт навсегда (раздел 8.8).

**Не умеет / ограничения**

- **Защита рассчитана на честную ошибку программиста, не на злой умысел** (раздел 9). С 0.16.0 скрипт исполняется
  в своём процессе, с 0.17.0 — не от root и без сети, если не включена галочка: ошибка скрипта рантайм и соседние
  блоки не роняет; опасные для контроллера операции в блоке недоступны (раздел 8.5).
- **Исполнитель один на контроллер**: блоки исполняются строго по очереди; долгий скрипт задерживает
  все блоки PyScript, стоящие за ним.
- **Время — только по надёжной опоре.** Вызов асинхронный: ответ приходит в одном из следующих тактов, промежутки
  между вызовами неравные, после остановки или правки скрипта его переменные начинаются заново. Поэтому время в
  скрипте считают по часам контроллера (`time.monotonic()`) или по сигналу программы ПЛК, поданному на вход, — но
  не числом вызовов. Согласование скриптов между собой и то, что должно сработать в каждом такте, делает только
  программа ПЛК (FBD) (раздел 8.9).
- **Граница времени — предел вызова + 100 мс**: долгий вызов на C (`time.sleep`, сеть, сжатие, огромное целое,
  тяжёлое регулярное выражение) и `except:` без класса в вечном цикле прерыванием не обрываются — процесс скрипта
  останавливается через 100 мс после предела (`−16`) и при следующем вызове загружается заново; до этого остальные
  блоки PyScript ждут (раздел 8.1). Скан при этом работает.
- **Память скрипта — до 64 МБ (`mem_mb`) сверх занятой при запуске**, подкачки на контроллере нет: больше —
  `MemoryError` (`−6`), процесс скрипта жив (с 0.16.0, раздел 9).
- **Все входы и выходы — real (float32)**: целые больше 16 777 216 теряют точность, `bool`/`int` — это 0.0/1.0…
- Сторонних пакетов нет (**numpy, scipy, pandas — нет**, ставить нечем) — только стандартная библиотека.
- Доступ к переменным ПЛК — только через входы и выходы блока; вызвать блок FBD из Python нельзя.
- Платформа: контроллер **SMH5 (aarch64) с прошивкой, где пакет `logix` = 260113**; компьютер — Windows
  с установленным SMLogix производителя 3.35.
- Проект, сохранённый нашей оболочкой, — формат 254 (с 23.10.2026; 253 — с 22.10, раньше 252): **SMLogix 3.35 его
  не откроет**, прежние сборки нашей оболочки (форматы 252, 253) — тоже; проекты 252 и 253 новая оболочка
  открывает (253 — по коду, в окне не проверялось).
- Отмена (Ctrl+Z) правки скрипта **со связью с файлом** невозможна — «Откат связанного файла невозможен»
  (файл на диске она бы не вернула); правка без связи отменяется вместе с входами, выходами и связями (3.1).
- **Старый блок PyScript производителя** (проекты SMLogix 3.35) **не исполняется** — с пакета 0.11.2 его
  раскладка не поддерживается: `result = −21` и строка в журнале (5.4). Реальных проектов с ним нет.
- Отладчика скриптов и справки в SMLogix нет — документация только эта.
- Скрипты прежнего проекта не удаляются с контроллера при загрузке нового (не исполняются, но лежат).
- Тревоги «исполнитель занят» и «много открытых файлов и соединений» — только выход `alarm` и системный журнал,
  штатной тревоги рантайма нет.
- Номер скрипта (`sid`) назначается при каждой сборке заново — опираться на него нельзя.

### 2.1. Контроллер

Один пакет **`logixpy`**:

- свой `logix` (штатный файл прошивки `dpkg-divert` уводит в `logix.vendor`), рядом с ним — процесс запуска
  скриптов `pyscript-host` (с 0.16.0), и `libtensorflowlite_c.so` в `/usr/local/lib` (нужна logix, в прошивке её нет);
- Python 3.13.16 в `/usr/local`: `libpython3.13.so.1.0`, стандартная библиотека `/usr/local/lib/python3.13` (с
  готовым байт-кодом), `/usr/local/bin/python3.13`. Ссылка **`/usr/bin/python3` ведёт на него** (ссылку пакета
  `python3-minimal` на 3.7 `dpkg-divert` уводит в `python3.debian`): системный `python3` прошивки нужен только
  `tuptime` (учёт загрузок), он проверен на 3.13.

Зависимости — `logix (= 260113)` и библиотеки прошивки (libssl1.1, zlib, bz2, lzma, sqlite3, uuid): на другой
прошивке `dpkg` откажет, так задумано (logix собран под её библиотеки). **Возврат через `dpkg` не предполагается**
— поставщик возвращает контроллер только полным форматированием.

**Установка перезапускает рантайм** (`service logix.sh restart`, ~2 с без управления) — делать на остановленном
объекте или в окно обслуживания. Ставится на свежую прошивку. Если на контроллере стоит прежний опытный пакет
рантайма — сначала снять его (`dpkg --purge --force-depends <прежний пакет>`), затем ставить этот (так проверено
на SMH5 26.10.2026):

```bash
scp logixpy_0.18.3-1_arm64.deb root@<IP>:/tmp/
```

```bash
ssh root@<IP> "dpkg -i /tmp/logixpy_0.18.3-1_arm64.deb && dpkg -s logixpy | grep -E 'Status|Version' && dpkg-divert --list | grep -E 'logix|python3' && python3 -V"
```

Python 3.7 прошивки после установки не используется никем (проверено на SMH5 22.10.2026) и может быть удалён —
освобождает ~25 МБ корня. `dpkg` это разрешает: зависимость `tuptime` от `python3` выполняет `logixpy` (после
этого `dpkg -r logixpy` откажет — пакет держит `tuptime`):

```bash
ssh root@<IP> "dpkg --purge python3 python3-minimal python3.7 python3.7-minimal libpython3.7-minimal libpython3.7-stdlib libpython3-stdlib && dpkg --audit"
```

Строка `PyScript: LOGIXPY 0.18.3, исполнитель запущен …` появляется в `/var/log/user.log` только когда
в загруженной программе есть блоки PyScript (без них интерпретатор не поднимается). Следом — «скрипты исполняются в
отдельных процессах (процесс запуска N) …»; если вместо неё «процесс запуска скриптов не поднялся (…)» — скрипты
работают в потоке рантайма, как до 0.16.0 (переустановить пакет).

Нужен установленный SMLogix производителя 3.35, хотя бы раз запущенный под тем же пользователем Windows.

## 3. Как это устроено

### 3.1. Путь скрипта: компьютер → проект → контроллер

1. В SMLogix блок PyScript (группа «Скрипты») ставится на поле; двойной щелчок — диалог блока:
   - **путь к файлу** `.py` и «Обзор…», галочка **«Сохранять связь с файлом»** (стоит по умолчанию), кнопки
     **«Перечитать файл»** (видна только со связью), «Редактировать», «Закрыть»; кнопки «Записать» с 22.10.2026 нет;
   - **выбранный файл сразу разбирается** (п. 2) и без ошибок становится скриптом блока; так же — путь,
     введённый руками, файл, изменённый вне диалога (при открытии диалога), правки из редактора (при возврате
     в диалог) и «Перечитать файл» (разбор даже не изменённого файла — для файла, изменённого другой
     программой). В сам блок скрипт и перестроенные по нему входы и выходы уходят при закрытии диалога;
   - «Редактировать» открывает редактор из настроек SMLogix (VS Code или Блокнот; нет файла — создаёт его из
     скрипта блока или по шаблону);
   - **ошибка разбора** — скрипт блока не меняется, в диалоге красная надпись «Ошибка в тексте программы!»,
     журнал **`%LOCALAPPDATA%\SMLogix\py.log`** (там же, где `logix.log`) — по каждой ошибке номер строки,
     текст строки и ошибка, все ошибки сразу — открывается редактором по умолчанию; «Закрыть» при ошибке
     спрашивает (в блоке остаётся прежний скрипт). Русская буква в латинском слове названа прямо: «кириллица
     в названии типа недопустима ("floаt")». Пропущенная запятая между элементами словаря выглядит как
     «недопустимый тип "float ⏎ 'b': float"» — тип захватил следующую строку. **Тексты ошибок — черновые, правятся в конце работ над оболочкой** (просьба
     пользователя 22.10.2026);
   - **без связи с файлом** текст живёт только в блоке, файл на диске не читается и не меняется:
     «Редактировать» выгружает текст блока во временную копию (`%TEMP%\sm_logix\pyedit\…`), при возврате в
     диалог изменённая копия разбирается, становится скриптом блока и удаляется (с ошибкой — остаётся, чтобы
     правку не потерять); «Обзор…» — разовая загрузка текста файла. Поставить галочку снова — если файл
     отличается от блока, диалог спросит, что взять;
   - **отмена (Ctrl+Z)**: правка без связи с файлом отменяется целиком — прежний скрипт, прежние входы и
     выходы и их связи (одна правка «Изменение скрипта блока PyScript»). Правку **со связью** отмена не
     откатывает — сообщение «Откат связанного файла невозможен» (файл остался бы новым, и диалог снова взял бы
     его); действия до такой правки тоже не отменяются. Нужна отмена — правьте без связи; вернуть файл —
     средствами редактора или хранилища версий. Текст сообщения тоже правится в конце работ;
   - меню «Опции → Синхронизировать скрипты Python» обновляет из файлов все блоки со связью (без связи —
     пропускает): входы и выходы перестраиваются так же, как из диалога (с 23.10.2026; раньше скрипт без входов
     ломал имена служебных входов, а связи убранных входов терялись насовсем). Все блоки — одна правка, отмена её
     не откатывает (блоки связаны с файлами) — «Откат связанного файла невозможен». Обходятся блоки верхнего
     уровня открытой программы; блоки PyScript внутри макросов, судя по коду, не обновляются (не проверялось).
2. Оболочка разбирает текст **без запуска Python**: словари `INPUTS`/`OUTPUTS` → число и имена входов и выходов;
   точка входа — функция `execute`.
3. При сборке оболочка в рабочей копии проекта (проект пользователя не меняется) раздаёт номера: **каждый
   блок со скриптом получает свой `sid`** (1…N в порядке блоков), даже если текст у копий одинаковый;
   `fid` = 0 (`execute`); скрытая константа `ver` = 20530 — признак редакции 2.
   Тексты пишутся в `%TEMP%\sm_logix\py\script<sid>.py` (UTF-8 без BOM).
4. Компилятор кладёт папку `py` в архив загрузки `load_files.zip`; контроллер распаковывает его штатно
   (`cd /projects; unzip -o`) — скрипты оказываются в **`/projects/py/script<sid>.py`**.
5. Рантайм logix при старте видит в программе блоки PyScript и поднимает исполнитель; блок в каждом такте
   ставит заявку `(sid, fid, x0…)` и забирает ответ.

### 3.2. Рантайм

- **Исполнитель** — один поток `pyexec` внутри logix, обычная политика планирования (не реального
  времени), на тех же ядрах, что поток скана `Step` (тот — SCHED_RR 30 и всегда вытесняет исполнитель).
- **Скрипт — в своём процессе** (с 0.16.0): при старте рантайма поднимается процесс запуска скриптов
  `pyscript-host` (Python с проверкой скрипта — ~0,5 с), и на первый вызов каждого номера скрипта он за несколько
  миллисекунд порождает его процесс (`pyscript <sid>` в списке процессов) — с тем же приоритетом и на тех же ядрах,
  что исполнитель. Исполнитель передаёт процессу входы и получает выходы, код и текст ошибки через общую память.
  Ошибка скрипта (вечный цикл, аварийное завершение) рантайм и соседние скрипты не задевает. Ключ `process = 0` —
  скрипты в потоке исполнителя, как до 0.16.0 (раздел 6).
- **Очередь заявок** — общая, по порядку постановки (= порядку блоков в программе), до 32 заявок
  (`max_queue`). У каждого блока не больше одной заявки в работе. Аргументы — **снимок входов в такте
  постановки**.
- **Ожидание в такте**: поставив заявку, скан ждёт ответ не дольше `wait,us` (по умолчанию 2000 мкс) и
  только если исполнитель был свободен; за цикл суммарное ожидание всех блоков — не больше `per_cycle_ms`
  (10 % такта); после порога `skip_at_ms` (80 % от него) оставшиеся блоки цикла не ждут вовсе. Не
  дождался — `result = 3`, вызов досчитывается, ответ отдаётся в одном из следующих тактов.
- **Предел на вызов**: сторожевой поток следит за идущим вызовом; дольше `tlim,ms` блока (или общего
  `per_call_ms`, 1000 мс) — просит интерпретатор прервать вызов (`Py_AddPendingCall`): на ближайшей
  границе байт-кода в скрипте возбуждается `pyexec.TimeLimit` (наследник **BaseException** — обычный
  `except Exception` его не ловит), код `−16`. Просьба повторяется раз в 50 мс, пока вызов не кончится.
  Не кончился за `kill_after_ms` (100 мс) после первой просьбы (глотает прерывание или застрял в вызове на C) —
  **процесс скрипта останавливается принудительно**: `−16` с тем же текстом, а следующий вызов загружает скрипт
  заново — его глобальные переменные начинаются с начальных значений (8.4).
- **Понижение приоритета**: на чьём вызове сработал сторож, тот вызов доигрывает с nice 19, а следующие
  вызовы этой функции начинаются пониженными, пока одна не уложится в предел.
- **Тревога «исполнитель занят»**: вызов идёт дольше `busy_alarm_ms` (2 × предел вызова = 2 с; для блока
  со своим `tlim,ms` — не раньше 2 × `tlim,ms`) — выход `alarm` у всех блоков и запись в журнал; снимается, когда
  вызов закончился.
- **Тревога «много открытых файлов и соединений»** (с 0.15.0): раз в секунду считается, сколько файлов, соединений
  и прочих дескрипторов открыто у рантайма (в работе — около 60 из 1024 возможных). Половина предела (`fd_alarm`,
  512) — выход `alarm` у всех блоков и запись в журнал с числом файлов и соединений; снимается, когда их снова не
  больше 90 % порога (461). Сама тревога ничего не закрывает (8.8, п. 7).
- **Загрузка скрипта** (импорт при первом вызове и после правки файла) не прерывается до
  `import_limit_ms` (10 с) — тяжёлые импорты успевают загрузиться.
- **Файл состояния** `/run/pyexec.status` (раз в секунду), **файлы ошибок** `/projects/py/script<sid>.txt`,
  **системный журнал** `/var/log/user.log` (раздел 7).

### 3.3. Жизнь заявки по тактам

| такт | `proc` | что происходит | `result` | `busy` | `done` |
|---|---|---|---|---|---|
| N | 1 | заявка поставлена, ответ успел за `wait,us` | код ответа (0) | 0 | 1 |
| N | 1 | заявка поставлена, ответ не успел | 3 | 1 | 0 |
| N+1… | 1 | вызов ещё идёт | 3 | 1 | 0 |
| N+k | 1 | ответ отдан (новая заявка — в следующем такте) | код ответа | 0 | 1 |
| N+k | 1 | то же при `wait,us < 0` (конвейер): ответ + сразу новая заявка | код ответа | 1 | 1 |
| — | 0 | заявок нет | 0 | 0 | 0 |

Выходы `y*` и `duration,us` меняются **только при успешном ответе** (`result = 0`); при `3` — прежние значения,
при ошибках — тоже прежние, кроме выходов, названных в словаре `SAFE` скрипта (5.5).
Ответ на заявку, поставленную до снятия `proc`, всё равно отдаётся (`done = 1`).

## 4. Как писать скрипт

### 4.1. Правила (их проверяют оболочка и рантайм)

1. Файл — **UTF-8**, на контроллере импортируется как модуль `script<sid>`.
2. **Объявление входов и выходов** — два словаря на верхнем уровне, имя **с начала строки**:
   ```python
   INPUTS = {
       'TEMP':  float,
       'LIMIT': float,
   }
   OUTPUTS = {
       'ALARM': bool,
   }
   ```
   - Имена — латиница, цифры, `_`, не с цифры (кириллица не принимается); до 256 в каждом словаре.
   - Типы — `float`, `bool`, `int`, `long` (`long` — строкой `'long'`). **Тип — только пометка**: все
     входы и выходы блока — real, аргументы приходят `float`, результаты уходят в real.
   - `INPUTS` обязателен (может быть пустым `{}`), в `OUTPUTS` — хотя бы один выход.
   - Разбор текстовый, без Python: словарь ищется по первому вхождению имени с начала строки — не
     заводите строк вида `INPUTS_OLD = …` выше настоящего объявления и не начинайте строки докстрингов
     словами `INPUTS`/`OUTPUTS`.
3. **Точка входа** — `def execute(...)` с начала строки, строчными. Ловушка: `def Execute` (с большой буквы)
   оболочка примет, а рантайм позовёт `execute` → `−3`. Вспомогательные функции называйте как угодно, кроме
   `execute`.
4. **Аргументы** — позиционные, в порядке словаря `INPUTS`, все `float`, ровно столько, сколько входов
   (`*args` и умолчания учитываются). Число проверяется до вызова: не сходится — `−13`.
5. **Результат** — кортеж или список **ровно из `len(OUTPUTS)` чисел** в порядке `OUTPUTS`; при одном
   выходе можно вернуть просто число. Годится всё, что переводится в `float` (`int`, `bool`, `float`).
   `None`, строка — `−15`; не та длина — `−14`; не кортеж/список/число — `−7`.
6. Исключение в функции — `−6`, текст с трейсбеком — в `/projects/py/script<sid>.txt`.
7. **Выходы при ошибке** — необязательный словарь `SAFE = {'имя выхода': число, ...}` с начала строки (раздел 5.5);
   без него при ошибке все выходы держат прежние значения.
Шаблон, который создаёт оболочка (кнопка «Редактировать» без файла):

```python
# -*- coding: utf-8 -*-

INPUTS = {
    'IN1': float,
}

OUTPUTS = {
    'OUT1': float,
}


def execute(in1):
    return (0.0,)
```

### 4.2. Примеры

Простой (проверен на стенде: сумма и произведение, отвечает в том же такте):

```python
INPUTS = {
    'a': float,
    'b': float,
}

OUTPUTS = {
    'sum':  float,
    'prod': float,
}


def execute(a, b):
    return (a + b, a * b)
```

Состояние между вызовами — глобальные переменные модуля (регулятор с гистерезисом; `SAFE` — нагрев при ошибке
выключить, раздел 5.5):

```python
INPUTS = {
    'T':    float,    # температура, °C
    'SP':   float,    # уставка, °C
    'HYST': float,    # зона нечувствительности, °C
}

OUTPUTS = {
    'HEAT': bool,     # включить нагрев
}

SAFE = {
    'HEAT': 0,        # при ошибке скрипта — нагрев выключить
}

_heat = False         # прошлое решение; живёт до правки файла, перезапуска или остановки скрипта


def execute(t, sp, hyst):
    global _heat
    if t < sp - hyst / 2:
        _heat = True
    elif t > sp + hyst / 2:
        _heat = False
    return (_heat,)
```

Решение зависит только от входов и прошлого решения, а не от времени, — поэтому годится для асинхронного вызова.
Если формуле нужен шаг по времени (фильтр, скорость изменения), берите его по часам контроллера `time.monotonic()`
или со входа от программы ПЛК, а не числом вызовов (раздел 8.9). У каждого блока (и у каждой его копии) своё
состояние; после остановки или правки скрипта `_heat` начинается с `False` (раздел 8.4).

Долгий вызов (проверен на стенде: ответ асинхронно, `tlim,ms` режет дольше предела):

```python
import time

INPUTS = {
    'ms': float,
}

OUTPUTS = {
    'echo': float,
}


def execute(ms):
    end = time.monotonic() + ms / 1000.0
    while time.monotonic() < end:
        pass
    return ms
```

### 4.3. Что считать быстрым

Бюджет: при такте 100 мс и `wait,us` 2 мс скрипт, который хочет отвечать в том же такте, должен укладываться
в ~1–1,5 мс вместе с холодным вызовом (50–60 мкс) — это порядка **тысячи простых строк** на вызов. Всё, что
дольше, работает асинхронно (ответ в следующих тактах) и задерживает остальные блоки PyScript. Оценка с ПК:
время на ПК × 50…80 (см. 3.4). Избегайте `statistics` в каждом вызове (на 100 числах — 2,3 мс), тяжёлых
импортов внутри функции (импорт — один раз, наверху файла), форматирования строк без нужды.

## 5. Входы и выходы блока, коды

### 5.1. Входы и выходы (редакция 2, код блока 4356)

| вход | тип | вид | смысл |
|---|---|---|---|
| `proc` | bool | видимый | разрешение вызова |
| `ver` | int | скрытый | признак раскладки 20530, ставит оболочка |
| `sid` | int | скрытый | номер скрипта, ставит оболочка при сборке |
| `fid` | int | скрытый | точка входа, всегда 0 (`execute`); ставит оболочка |
| `tlim,ms` | int | видимый, 0 | предел на вызов этого блока, мс; ≤ 0 — общий `per_call_ms` |
| `wait,us` | int | видимый, 0 | ожидание ответа в такте, мкс; 0 — общее `wait_us`; < 0 — не ждать и конвейер |
| `x0…` | real | видимые, до 256 | аргументы; имена — из `INPUTS` |

| выход | тип | смысл |
|---|---|---|
| `result` | int | 0 — успех; 3 — в работе; отрицательные — ошибки (5.2) |
| `duration,us` | long | длительность последнего успешного вызова, мкс — по часам (5.3) |
| `busy` | bool | заявка в работе (при конвейере — и в такте ответа) |
| `done` | bool | в этом такте отдан ответ (импульс на такт) |
| `alarm` | bool | тревога «исполнитель занят» или «много открытых файлов и соединений» (3.2) — общая для всех блоков |
| `y0…` | real | результаты; имена — из `OUTPUTS`; при ошибке — прежние или из `SAFE` (5.5) |

На блоке служебные входы и выходы подписаны именем и единицей через запятую (с архива 02.11.2026): `ms` —
миллисекунды, `us` — микросекунды. В проектах прежних архивов они назывались `tlim`, `wait`, `duration`
(такие проекты не поддерживаются — раздел 2).

### 5.2. Коды `result`

| код | смысл | что делать |
|---|---|---|
| 0 | успех | — |
| 3 | в работе: ответа ещё нет, выходы прежние | норма для долгого скрипта; долго — смотреть очередь (8.1) |
| −1 | интерпретатор не поднялся | журнал logix; пакет установлен? |
| −2 | скрипт не загружается: нет файла, синтаксическая ошибка, исключение в коде верхнего уровня, ошибка в `SAFE` (5.5) | `script<sid>.txt` |
| −3 | нет функции `execute` | точка входа (4.1, п. 3) |
| −4 | (зарезервирован, как у производителя; не выдаётся) | — |
| −5 | имя точки входа — не функция | — |

| −7 | результат не кортеж/список (и не число при одном выходе) | 4.1, п. 5 |

| −14 | вернула не столько значений, сколько выходов | сверить `OUTPUTS` и `return` |
| −15 | элемент результата не число (`None`, строка) | — |

При любом отрицательном коде, кроме `−21`, выходы, названные в словаре `SAFE` скрипта, принимают его значения
(5.5); остальные выходы и `duration,us` держат прежние.

### 5.3. Что показывает `duration,us`

Время от начала до конца вызова функции **по часам**, а не чистая работа Python. Очередь и такты скана в
него не входят, но входят паузы, когда скан вытеснил исполнитель (они на одном ядре). Если `wait,us` больше
времени вызова — `duration,us` близко к чистому счёту; если меньше — скан перестаёт ждать и продолжает
программу, а остаток такта попадает в `duration,us` (замер: вызов 59 мкс при `wait,us = 20` мкс показывал
медиану 351, максимум 819 мкс). Скан при этом не задерживается. Чтобы оценить «тяжесть» скрипта, мерить с
`wait,us` больше времени вызова. Предел `tlim,ms` считается по тем же часам. При `proc = 0` `duration,us` замирает на
последнем вызове.

### 5.4. Прежняя раскладка (блок производителя 3.35) — не поддерживается

`proc, script, func, in, out, x0…x9 | result, duration, y0…y9`. С пакета 0.11.2 (решение 23.10.2026: реальных
проектов с ним нет) такой блок **не исполняется**. Рантайм узнаёт редакцию 2 по входу `ver` (20530) и числу
входов и выходов (не меньше 6 и 5); любому другому блоку каждый такт ставит `result = −21`, остальные выходы
не трогает и один раз на блок пишет в `/var/log/user.log`: «PyScript: блок не редакции 2 (второй вход N, у
редакции 2 — 20530) не исполняется, result -21 — соберите проект SMLogix с блоком PyScript редакции 2» (или
«блок (входов N, выходов M) — меньше служебных входов и выходов редакции 2 (6 и 5)…»). Наша оболочка такой
блок не создаёт: секция `[PyScript]` в ini — редакции 2.

### 5.5. Выходы при ошибке: SAFE

По умолчанию при ошибке (`result` < 0) выходы `y*` **держат прежние значения** — последнего успешного ответа (до
первого успешного ответа — начальные значения). Программа ПЛК, которая не смотрит на `result`, так и работает на старых данных. Необязательный
словарь **`SAFE`** в скрипте задаёт, какие выходы при ошибке принимают какие значения (с пакета 0.18.0):

```python
INPUTS = {'TEMP': float}
OUTPUTS = {
    'HEAT': bool,
    'POWER': float,
    'TREND': float,
}
SAFE = {          # при ошибке: нагрев выключить, мощность — 0; TREND держит прежнее значение
    'HEAT': 0,
    'POWER': 0.0,
}
```

- **Когда действует** — при любом ответе блока с ошибкой, `result` < 0: исключение в функции и нехватка памяти
  (`−6`), прерывание по пределу времени и остановка зависшего скрипта (`−16`), аварийное завершение скрипта (`−6`),
  запрещённое в скрипте (`−22`), скрипт не загрузился (`−2`, в том числе из-за синтаксической ошибки: `SAFE`
  читается из текста и без загрузки скрипта), не тот результат (`−7`, `−13`…`−15`), очередь полна (`−20`). Выходы
  из `SAFE` принимают его значения в том же такте, в котором приходит `result` с ошибкой (`done = 1`); выходы,
  которых в `SAFE` нет, и `duration,us` держат прежние значения. Успешный ответ — как всегда: все `y*` от скрипта.
- **Когда не действует**: `result = 3` (ответа ещё нет — выходы прежние; ответ придёт кодом 0 или ошибкой, самое
  позднее `−16` после предела времени); `−21` (блок не редакции 2 — его выходы не трогаются); на контроллере нет файла
  скрипта (`−2` «нет файла …») или номер скрипта вне диапазона (`−10`) — `SAFE` взять неоткуда, выходы держат
  прежние значения.
- **Без `SAFE` или `SAFE = {}`** — все выходы при ошибке держат прежние значения.
- **Правила записи** (их проверяют SMLogix и контроллер): имя `SAFE` с начала строки, сразу `=` и словарь `{…}`
  как есть в тексте — без выражений и вызовов (`dict(...)`, `{…} | X`, `SAFE: dict = …` не годятся); ключ — имя
  выхода из `OUTPUTS` в кавычках, без повторов; значение — число: `0`, `-1`, `2.5`, `1e3` (не `True`/`False`, не
  строка, не выражение, не `0x10`, не `1_000`), по модулю не больше 3,4·10³⁸ (real); объявление одно. Значение
  уходит в выход как real: для `bool` пишите 0 или 1. Разбор — по тексту, как у `INPUTS`/`OUTPUTS` (4.1, п. 2):
  строки докстрингов не начинайте словом `SAFE`.
- **Ошибка в `SAFE`** — скрипт **не загружается**: `result −2`, выходы держат прежние значения, в `script<sid>.txt` —
  «скрипт не загружен — строка N: SAFE…» с одной из причин: `ожидается словарь — SAFE = {'имя выхода': число, ...}`,
  `объявлен повторно`, `не найдена закрывающая скобка объявления`, `не разобран элемент "…"`, `имя выхода должно
  быть в кавычках`, `кириллица в имени выхода недопустима`, `нет выхода "…" в OUTPUTS`, `выход "…" повторён`,
  `SAFE.<выход>: значение … — нужно число`, `SAFE.<выход>: значение … — вне пределов real (±3.4e38)`; в конце —
  «(раздел 5.5)». Ту же ошибку SMLogix показывает в `py.log` при выборе файла, но скрипт в блок всё равно принимает —
  исправьте `SAFE` до загрузки проекта (раздел 10).
- Контроллер берёт `SAFE` из текста скрипта сам: значения подставляются, даже когда зависший скрипт остановлен,
  завершился аварийно или не загрузился. После правки файла скрипта прямо на контроллере новый `SAFE` действует со
  следующей ошибки.
- `SAFE` — подстраховка, не замена проверки: программе ПЛК по-прежнему стоит смотреть на `result` и `done`.

| `y*` не меняются, `result` ≠ 0 | при ошибке выходы держат прежнее (кроме объявленных в `SAFE`) | код `result`; безопасные значения при ошибке — `SAFE` (5.5) |
| `result = −2`, в `script<sid>.txt` «скрипт не загружен — строка N: SAFE…» | ошибка в объявлении `SAFE` | 5.5 |
| значение «не то» в 7-м знаке | real — float32 | 8.3 |
| в `/projects/py` лишние `scriptN.py` | скрипты прежнего проекта | не мешают; удалить вручную |
| диалог блока: «Ошибка в тексте программы!», в `py.log` «недопустимый тип "float ⏎ 'b': float"» | в конце строки элемента словаря нет запятой | поставить запятую |

## 8. Особенности исполнения (всё учтённое на сегодня)

### 8.1. Время и очередь

1. **Исполнитель один, очередь общая** — вызовы строго по очереди в порядке постановки (= порядку блоков в
   программе). Долгий вызов задерживает всех, кто за ним: замер — `slow` 300 мс при такте 100 мс и
   `sumprod` за ним — оба блока по одному ответу раз в 5 тактов. Предел задержки чужих блоков — `tlim,ms`
   долгого блока. Это свойство архитектуры, а не сбой.
2. **Скан не ждёт дольше `wait,us`** (по умолчанию 2 мс) и суммарно за цикл не дольше 10 % такта; после 80 %
   этой суммы оставшиеся блоки цикла не ждут вовсе. Не дождался — `result = 3`, ответ позже.
3. Ответ на заявку отстаёт от её входов: входы — снимок такта постановки.
4. Без конвейера блок в такте ответа новую заявку не ставит: скрипт, не уложившийся в `wait,us`, отвечает
   не чаще раза в два такта. **Конвейер (`wait,us < 0`)**: в такте ответа сразу ставится следующая заявка —
   ответ каждый такт для вызова короче такта; `busy` не опускается, `done` горит в каждом такте ответа;
   исполнитель простаивает меньше — соседи ждут дольше (замер: `slow` 30 мс с конвейером — 1 ответ на такт,
   `sumprod` за ним — раз в два такта); после снятия `proc` придёт ещё один ответ.
5. **`duration,us` — по часам** и включает вытеснения сканом (5.3).
6. **Холодный вызов** — 50–60 мкс даже для пустой функции (кэши процессора остывают между тактами).
7. **Прерывание приходит только на границе байт-кода Python.** Вызов на C (`time.sleep(5)`, `re` с
   бэктрекингом, `zlib`/`bz2`/`lzma` больших данных, сокет без таймаута, `10**10**7`) прерыванием не обрывается:
   с 0.16.0 такой вызов, не вернувшийся за предел + 100 мс, останавливается вместе с процессом скрипта (3.2), до
   этого он держит исполнитель — все блоки ждут.
8. **`except:` без класса и `except BaseException:`** ловят `pyexec.TimeLimit`. Внутри вечного цикла такой
   скрипт прерыванием не остановить: с 0.16.0 его процесс останавливается через 100 мс после просьбы, `−16`, и
   скрипт загружается заново (глобальные переменные — с начала); до остановки остальные блоки PyScript ждут.
   (До 0.16.0 исполнитель был занят навсегда, выход — только перезапуск рантайма.) Пишите `except Exception:`.
9. Исполнитель живёт на ядре потока скана с обычным приоритетом: управление он не задерживает, но
   застрявший скрипт забирает всё не-RT время этого ядра (обычные потоки logix на нём делят остаток);
   понижение приоритета (nice 19) это смягчает.
10. **Ждать внутри вызова нельзя**: `time.sleep`, `select.select` (и `input`, 8.5) в блоке запрещены (`−22`).
    Промежуток между вызовами не равен такту и не постоянен (пп. 1–4) — время не считайте числом вызовов: только
    по часам контроллера или по сигналу программы ПЛК (раздел 8.9).

### 8.2. Загрузка и правка скрипта

1. Скрипт импортируется **при первом вызове** после старта рантайма (не при старте): первые такты —
   `result = 3`. Код верхнего уровня (импорты, таблицы) исполняется один раз. Загрузка не прерывается
   10 с (`import_limit_ms`); дольше (вечный цикл наверху файла) — `−16` «при загрузке».
2. Цена первого импорта — в приложении (сводная таблица; Python 3.13, 22.10.2026): `math` ~3 мс, `datetime`
   ~7 мс, `random` ~21 мс, `hashlib` ~24 мс, `json` ~44 мс, `socket` ~53 мс, `statistics` ~92 мс, `ssl` ~164 мс,
   `urllib.request` ~550 мс, `asyncio` ~830 мс (на 3.7 было ~420 мс — без нужды не импортировать).
3. **Правка файла на контроллере** подхватывается без перезапуска: перед каждым вызовом сверяется время
   изменения файла; изменился — `importlib.reload`. Ошибочная версия файла повторно не компилируется (ждёт
   следующей правки). С новой версией прежние ошибки её функций забываются. Перед загрузкой новой версии
   сбрасываются кэши поиска файлов — напрямую у искателей `sys.path_importer_cache`, не через
   `importlib.invalidate_caches()`: та в Python 3.10+ подтягивает `importlib.metadata` и ещё ~60 модулей
   (на SMH5 ~0,7 с при первой загрузке и память logix; найдено и исправлено 22.10.2026).
4. **`reload` исполняет код заново в том же пространстве имён**: переменные, удалённые из новой версии,
   остаются от старой; присвоенные наверху файла — переприсваиваются.
5. **Функция и число её аргументов запоминаются один раз на версию файла.** Если скрипт сам на лету
   переприсвоит имя своей функции (`global execute; execute = …`), блок до правки файла зовёт прежнюю.
6. Загрузка нового проекта — это перезапуск рантайма: интерпретатор новый, всё состояние скриптов
   сброшено.
7. Каталог скриптов `/projects/py` стоит **в конце** `sys.path`: файл `random.py` рядом не подменит
   стандартный модуль. Скрипт может импортировать другой скрипт проекта (`import script2`) — но номера
   меняются от сборки к сборке, не делайте так. Своих модулей-помощников оболочка не возит — всё в одном файле.
8. `__pycache__` не пишется (`sys.dont_write_bytecode`) — флеш не изнашивается.
9. Скрипты прежнего проекта с номерами, которых нет в новом, остаются в `/projects/py` (прошивка чистит
   только `Pics`); не исполняются.

### 8.3. Данные

1. **Все входы и выходы — real (float32).** Вход 0.1 приходит как `0.10000000149011612`; сравнивать на равенство
   нельзя — только с допуском. Выход переводится в float32: целые больше 16 777 216 теряют точность
   (33 554 433 → 33 554 432), около 7 значащих цифр.
2. `bool`/`int` в объявлении — только пометка: приходит `0.0`/`1.0`; проверять `x > 0.5`, для индексов —
   `int(x)` (`range(x)` с float — исключение `−6`).
3. Возврат `True`/`False`, `int`, `float` — годится; `None`, строка, `Decimal` без перевода — нет (`−15`).
4. `NaN` и бесконечность уходят в ПЛК как есть — проверяйте сами.
5. Вычисления внутри — double (64 бита). Перевод целого в строку — не длиннее 4300 цифр (`ValueError`), само
   вычисление огромных целых не ограничено.

### 8.4. Состояние

1. Глобальные переменные модуля живут между вызовами — до правки файла (`reload`), перезапуска рантайма или
   (с 0.16.0) принудительной остановки или аварии процесса скрипта (3.2): тогда скрипт загружается заново и
   переменные начинаются с начальных значений. Обычное прерывание по пределу (`−16`, скрипт послушался) их не
   сбрасывает.
2. **У каждого блока свой модуль**, даже у копий с одинаковым скриптом: свой файл `script<sid>.py`, свои глобальные
   переменные и свой файл ошибки — копии состояние не делят. Общего состояния между блоками нет: данные из блока в
   блок передаёт программа ПЛК — выход одного блока на вход другого (раздел 8.9); общая папка файлов есть только у
   копий с одним и тем же скриптом (8.8). Скрипт копируется вместе с блоком и через буфер обмена, и при отмене
   действий.
   (В архиве от 19.10.2026 копии с одинаковым скриптом делили один модуль, а вставленная копия теряла скрипт.)
3. Состояние в памяти не переживает перезапуск. Сохранить его можно в файл — только с галочкой «Разрешить операции
   с файлами» и только в папку скрипта (8.8): на флеш — редко (износ), часто меняющееся — в папку `ram/…` в ОЗУ
   (пропадает при выключении питания).

### 8.5. Процесс, ОС, ввод-вывод

1. С 0.16.0 скрипт — в **своём процессе** `pyscript <sid>`, текущий каталог `/projects`, ядро — как у скана; до
   0.16.0 (и при `process = 0`) — поток внутри процесса logix. С 0.17.0 этот процесс — под **непривилегированным
   пользователем** (не root), без галочки «сеть» — без доступа к сети совсем, каталоги, открытые на запись всем
   (`/tmp` и прочие), ему не видны; писать он может только в свою папку (раздел 8.8). Процессные настройки
   (`os.chdir`, `os.umask`, `os.environ`/`putenv`, `locale.setlocale`, `resource.setrlimit`,
   `sys.setrecursionlimit`/`settrace`/`setswitchinterval`, `gc.disable`, `signal.*`, `faulthandler`) в блоке
   запрещены (код `−22`): в потоке logix они меняли бы весь рантайм — например, `signal.signal` ставил обработчик
   сигнала всему logix (проверено зондом 20.10.2026).
2. **`os._exit`, `os.abort`, `os.kill(os.getpid(), …)`** в блоке запрещены. В процессе скрипта (0.16.0) они
   завершили бы только его — `−6` «скрипт аварийно завершён», при следующем вызове он загрузится заново; в потоке
   logix — рантайм (управление встало бы до перезапуска). `sys.exit()`/`exit()` безопасны — это исключение, код
   `−6`.
3. **`subprocess`, `os.system`, `os.popen`, `os.fork`, `multiprocessing`, `pty`** порождают процессы — в блоке
   запрещены (при `process = 0`, в потоке исполнителя, это был бы fork многопоточного logix с потоками реального
   времени). Так же,
   неочевидно, **`platform.platform()`, `platform.processor()`, `platform.uname()`** — при первом вызове
   запускают `uname -p` (проверено на SMH5 22.10.2026); версию ядра брать из `os.uname()`.
4. **`ctypes` в этой сборке Python нет** (не собран намеренно: прямой доступ к памяти процесса, ошибка — авария
   скрипта, при `process = 0` — авария logix) — `import ctypes` даёт `ModuleNotFoundError` (наверху файла — код
   `−2`, в функции — `−6`).
   Вызвать библиотеку на C из скрипта нельзя.
5. **Потоки** (`threading`, `concurrent.futures`) в блоке запрещены (`−22`): они жили бы после ответа блока, вне
   пределов времени. Периодическую работу делайте вызовами блока: при каждом вызове скрипт сверяется с часами
   контроллера или со входом от программы ПЛК (раздел 8.9).
6. `print` и `logging` по умолчанию пишут в stdout/stderr logix — это **`/dev/null`**: вывода не видно
   нигде. `input()` в блоке запрещён (`−22`): вводить нечего. Отладочный вывод — через выходы блока или (редко, с
   галочкой файлов) в свой файл в папке скрипта (раздел 8.8).
7. **Файлы — только с галочкой «Разрешить операции с файлами»** и только в папке скрипта (раздел 8.8). Без
   галочки открыть файл, обойти каталог, удалить, переименовать — нельзя, попытка прерывается кодом `−22`.
8. **Сеть и COM-порты — только с галочкой «Разрешить работу с сетью»** (раздел 8.8). Без галочки попытка создать
   сокет, обратиться по сети или открыть порт прерывается кодом `−22`.
9. Локаль процесса — `en_US.UTF-8`, кодировки — UTF-8; часы: `time.monotonic()` — для промежутков, и внутри
   вызова, и между вызовами (не переводится), `time.time()` — календарное время (переводится при установке и
   синхронизации часов — промежуток по нему может прыгнуть); часовой пояс устройства может быть UTC (раздел 8.9).
10. Памяти мало (~490 МБ на всё устройство, подкачки нет): большие списки и словари растят процесс скрипта (до
    0.16.0 — сам logix). С 0.16.0 у процесса скрипта свой предел памяти `mem_mb` (64 МБ запаса на данные) — сверх
    него `MemoryError` (код `−6`), процесс жив; при нехватке памяти всего контроллера ядро убивает процесс скрипта
    (`oom_score_adj = 1000`), а не службы. Импорт всей стандартной библиотеки — ~29 МБ (опись 22.10.2026:
    13,6 → 41,7 МБ) — он тоже в счёт запаса. Процесс скрипта сам по себе занимает ~0,2 МБ своей памяти — остальное
    общее с процессом запуска скриптов.

### 8.6. Ошибки и файлы ошибок

1. Текст ошибки пишется в `script<sid>.txt` только при смене текста; ушла ошибка — файл удаляется. Прерывание
   пишет постоянный текст «прерван — превышен предел времени на вызов» (повторы не пишут флеш).
2. Файлы ошибок прошлого запуска рантайм убирает при старте (они уже неверны).
3. Число аргументов проверяется **до** вызова — ошибка схемы не выглядит исключением.
4. После прерывания интерпретатор исправен, следующий вызов идёт обычно; утечки памяти на прерывание нет
   (1001 прерывание за 5 минут — память ровно). Принудительная остановка процесса скрипта (3.2) пишет тот же текст
   «прерван — превышен предел времени на вызов» (при загрузке — «… при загрузке script<sid>.py»), аварийное
   завершение — «скрипт аварийно завершён (сигнал N) — при следующем вызове он загрузится заново».

### 8.7. Python 3.13 вместо 3.7 (с пакета 0.11, 22.10.2026): что изменилось для скрипта

Python 3.7 был только в тестовых версиях рантайма (пакеты до 0.11); переносить с него нечего — сравнения здесь и
в 3.4 даны для справки.

1. **Можно**: `:=`, `match`, `f'{x=}'`, только-позиционные параметры `/`, `str.removeprefix/removesuffix`,
   `dict | dict`, `math.prod/isqrt/dist`, `statistics.fmean`, `functools.cache`, `itertools.pairwise/batched`,
   новые модули `zoneinfo`, `graphlib`, `tomllib`. Трейсбек в `script<sid>.txt` подчёркивает место ошибки (`^^^`).
2. **Нет модулей, которые были на 3.7** (сверка описей 20.10 и 22.10.2026): удалены в Python 3.8–3.13 —
   `aifc`, `asynchat`, `asyncore`, `audioop`, `binhex`, `cgi`, `cgitb`, `chunk`, `crypt`, `distutils`,
   `dummy_threading`, `formatter`, `imghdr`, `imp`, `macpath`, `mailcap`, `nis`, `nntplib`, `ossaudiodev`,
   `parser`, `pipes`, `smtpd`, `sndhdr`, `spwd`, `sunau`, `symbol`, `telnetlib`, `uu`, `xdrlib`
   (`multiprocessing.semaphore_tracker` → `resource_tracker`); **не собраны** в нашей сборке — `ctypes`, `curses`,
   `readline`, `dbm.ndbm`; убрана справка `pydoc_data` (`help('тема')` не работает). `collections.abc` есть.
3. Скорость на SMH5 — на уровне 3.7 (раздел 3.4); импорт `asyncio`, `statistics`, `urllib.request` дороже, `random`,
   `hashlib`, `datetime`, `sqlite3` — дешевле.
4. Прерывание по пределу (`pyexec.TimeLimit`) на 3.13 чаще вырывается из цикла, который глотает исключения, —
   но опираться на это нельзя: `except:` и `except BaseException` по-прежнему не писать.
5. `platform.platform()` пишет `…-with-glibc2.28` вместо `…-with-debian-10.12` (дистрибутив больше не определяется).

### 8.8. Файлы, сеть и COM-порты: галочки в свойствах блока (с 27.10.2026)

В свойствах блока PyScript, под строкой состояния, — три галочки:

| галочка | что разрешает | что SMLogix пишет в скрипт |
|---|---|---|
| «Разрешить операции с файлами» | чтение и запись файлов **только в папке скрипта** на контроллере: `/projects/pydata/<имя скрипта>/` | `'files': 'write'` |
| «Разрешить работу с сетью» | сеть (`socket`, `http`, `urllib`, `ssl`, `ftplib`, …) и **COM-порты** контроллера `/dev/ttyS*` (модули `termios`, `tty` — скорость, чётность) | `'network': True` |
| «Сделать не редактируемым» | закрепление: скрипт навсегда теряет возможность правки | `'LOCKED': True` |

- Поставить галочку файлов или сети — SMLogix спросит: «Включение данной функции должно производиться
  исключительно квалифицированным персоналом и вызывает отказ в гарантийном обслуживании данного ПЛК» —
  «Да, я понимаю» / «Нет, я отказываюсь». Снять галочку — без вопроса.
- Галочка дописывает в текст скрипта (перед `INPUTS`) словарь и убирает его, когда все галочки сняты:
  ```python
  SECURITY = {
      'files': 'write',
      'network': True,
  }
  ```
  Со связью с файлом правится и файл на диске. Руками словарь не правьте — пользуйтесь галочками. Если открытый
  файл разрешает больше, чем текст в блоке (словарь дописали в другом месте), SMLogix задаёт тот же вопрос; «Нет» —
  скрипт не принимается, в блоке остаётся прежний, в `py.log` — «Отказ от повышения уровня доступа: работа с
  файлами» (или «… работа с сетью»).
- «Сделать не редактируемым» — вопрос «Скрипт навсегда потеряет возможность редактирования» («Да, я понимаю» /
  «Нет, отказываюсь»). После «Да» правка, связь с файлом, путь и все галочки неактивны навсегда; заменить скрипт
  можно только другим файлом через «Обзор...». Отмена (Ctrl+Z) закрепление не возвращает.

**Папка скрипта.** С галочкой «Разрешить операции с файлами» корень файловой системы для скрипта — его папка на
контроллере `/projects/pydata/<имя скрипта>/` (имя — как у файла скрипта в SMLogix, без `.py`); создаётся сама.

1. **Любой путь ведёт внутрь папки скрипта**: `open('data.csv', 'w')` и `open('/data.csv', 'w')` — один и тот же
   файл; `'/log/t.csv'` — подпапка `log` папки скрипта (создать её — `os.makedirs('/log', exist_ok=True)`); `..` выше
   папки не уводит. Так же работают `os.remove`, `os.rename`, `os.listdir`, `os.makedirs`, `os.path.exists`,
   `pathlib` и т. п. Готовая переменная `DATA_DIR` — полный путь папки на контроллере (с ней тоже можно).
2. **`ram/…` — папка скрипта в ОЗУ**: `open('ram/last.txt', 'w')`, `os.listdir('ram')`. Не изнашивает флеш-память,
   но **пропадает при выключении питания и перезагрузке**. Для того, что перезаписывается часто.
3. Пределы: **на флеше — 4 МБ на скрипт и 16 МБ на все скрипты**, **в ОЗУ — 64 КБ на скрипт и 1 МБ на все**
   (`files_mb`, `files_total_mb`, `ram_kb`, `ram_total_kb` в `pyexec.conf`, раздел 6). Переполнение — обычная ошибка
   «нет места» (`OSError`, errno 28: «место для файлов скрипта исчерпано (4 МБ)», в ОЗУ — «место в папке ram
   исчерпано (64 КБ)»), до записи; её можно перехватить `except OSError:` и удалить старые файлы — читать и удалять
   свои файлы можно всегда. Не перехваченная — код `−6`.
4. Копии блока с одним и тем же скриптом делят одну папку. Папка на флеше переживает загрузку проекта и
   перезагрузку.
5. **Флеш-память изнашивается** от частой записи: то, что меняется каждый такт, — в `ram/`; на флеш пишите редко
   (вход `proc` раз в минуту и т. п.).
6. Включённые разрешения контроллер записывает в свой журнал (какой скрипт и что разрешено) — это след для
   гарантийного обслуживания.
7. **Открытый файл, соединение или COM-порт занимает место в общем пределе рантайма (1024 на всё), пока его не
   закроют.** Открывайте через `with open(…) as f:` (закрывается сам), соединения закрывайте (`with socket…`,
   `s.close()`), открытые не складывайте в глобальные списки на каждый вызов. Если открытых станет много (512),
   поднимется тревога — выход `alarm` и запись в журнале (3.2, раздел 7); снимается, когда их снова не больше 461.
   Тревога ничего не закрывает: исправить скрипт; перезапуск рантайма закрывает всё.

**COM-порты.** `open('/dev/ttyS2', 'r+b', buffering=0)` — порт настоящий (не папка скрипта); скорость и чётность —
`termios.tcsetattr`. Ждать ответа внутри вызова нельзя (`select.select` и `time.sleep` в блоке недоступны и с
галочкой): читайте порт без ожидания — `termios` с `VMIN = 0` и `VTIME = 0`, — пришедшее копите в переменной
скрипта, а тайм-аут ответа считайте по `time.monotonic()` от момента запроса или берите от программы ПЛК (раздел
8.9). Занят ли порт другой службой контроллера (например, обменом Modbus по настройке проекта), SMLogix не
проверяет: порт освобождают настройками проекта. Консоль контроллера (`/dev/ttyFIQ0`) недоступна.

Пример — последнее значение каждый вызов в ОЗУ, журнал на флеше раз в минуту. Опора времени здесь — программа
ПЛК: она прибавляет 1 к входу `N` раз в минуту; изменившийся номер скрипт заметит при любом следующем вызове, а
одиночный импульс мог бы пропустить. Годятся и часы контроллера — `time.monotonic()` (раздел 8.9):

```python
SECURITY = {
    'files': 'write',
}

INPUTS = {
    'T': float,
    'N': float,       # номер записи: программа ПЛК прибавляет 1 раз в минуту (раздел 8.9)
}

OUTPUTS = {
    'ok': bool,
}

import os
import time

last_n = None


def execute(t, n):
    global last_n
    with open('ram/last.txt', 'w') as f:          # каждый вызов — в ОЗУ: флеш не изнашивается
        f.write('%.2f' % t)
    if int(n) == last_n:                          # минута по счёту FBD ещё не сменилась
        return (True,)
    last_n = int(n)
    try:
        with open('/temp.csv', 'a') as f:         # раз в минуту — на флеш, в папку скрипта
            f.write('%d;%.2f\n' % (time.time(), t))   # календарная метка времени — для записи годится
        return (True,)
    except OSError:                               # папка переполнена — начать журнал заново
        os.remove('/temp.csv')
        return (False,)
```

### 8.9. Время в скрипте — по надёжной опоре; что делает только программа ПЛК (FBD)

Скрипт исполняется **асинхронно**: не в такте программы ПЛК, а по заявке, в общей очереди. Поэтому:

- ответ приходит в такте постановки или в одном из следующих (`result = 3` — ответа ещё нет), а входы — снимок
  такта постановки (8.1, пп. 2–3);
- промежутки между вызовами одного блока не равны такту и не постоянны: их удлиняют долгие соседние скрипты,
  ожидание `wait,us`, конвейер, загрузка скрипта после правки (8.1, 8.2);
- вызов, не уложившийся в предел, прерывается (`−16`): его ответа нет, выходы держат прежние значения или берут
  `SAFE` (5.5);
- после принудительной остановки или аварии процесса скрипта, правки файла, перезапуска рантайма глобальные
  переменные начинаются заново (8.4).

**Правило: считать время в скрипте можно, но только по опоре, которая отмеряет настоящее время**, — не числом
вызовов или тактов («10 вызовов — это 1 с» неверно: промежутки неравные). Опора:

- **часы контроллера**: промежутки — по `time.monotonic()` (его не переводят); календарь, расписание и метки для
  записи — по `time.time()` и `datetime` (их переводят при установке и синхронизации часов — промежуток по ним
  может прыгнуть);
- **сигнал программы ПЛК** (она работает в реальном времени), поданный на вход: прошедшее время в секундах, шаг,
  номер периода, признак «прошёл период»;
- короткие промежутки **внутри одного вызова** (замер длительности, тайм-аут цикла) — по `time.monotonic()`.

Ждать внутри вызова нельзя (`time.sleep`, `select.select` — `−22`, 8.1, п. 10): скрипт запоминает момент и
сверяется с ним при следующих вызовах. Точность отсчёта в скрипте — не лучше промежутка между вызовами (ответ может
прийти на такт и позже), а накопленное в его переменных (момент события, интеграл, наработка) пропадает, когда
скрипт начинается заново. Где это недопустимо — считайте в программе ПЛК.

Пример — опора на часы контроллера:

```python
import time

INPUTS = {
    'run': bool,       # насос включён
    'p':   float,      # давление, бар
}
OUTPUTS = {
    'no_rise': bool,   # давление не поднялось за 30 с после пуска
}

_t_run = None          # момент пуска по часам контроллера; после перезапуска скрипта — с начала

def execute(run, p):
    global _t_run
    if not run:
        _t_run = None
        return (False,)
    if _t_run is None:
        _t_run = time.monotonic()      # пуск замечен первым вызовом после включения
    return (time.monotonic() - _t_run > 30.0 and p < 1.5,)
```

То же с опорой на программу ПЛК: таймер в FBD отсчитывает, сколько насос работает, и подаёт это на вход
(ответ берите по `done = 1`):

```python
INPUTS = {
    't_on': float,     # сколько секунд насос уже работает — отсчитывает таймер в FBD
    'p': float,        # давление, бар
}
OUTPUTS = {
    'no_rise': bool,   # давление не поднялось за 30 с после пуска
}

def execute(t_on, p):
    # опора времени — таймер в программе ПЛК
    return (t_on > 30.0 and p < 1.5,)
```

**Только программа ПЛК (FBD)**:

- **согласует скрипты между собой**: у каждого блока свои переменные (8.4), в каком такте ответит каждый блок,
  заранее не известно, — данные из скрипта в скрипт передаёт программа ПЛК (выход одного блока — на вход другого),
  очерёдность, взаимные блокировки и выбор ведущего задаёт тоже она;
- **отвечает в каждом такте**: защиты, блокировки, аварийный останов — в FBD; скрипт может опоздать или не
  ответить, `SAFE` (5.5) — только страховка;
- **следит за самим скриптом**: пришёл ли ответ (`done`, `result`), нет ли тревоги (`alarm`), сколько ответа нет —
  сторожевой таймер в FBD.

## 9. Как PyScript защищает контроллер от ошибки скрипта

**Модель**: ошибка в скрипте не должна мешать работе контроллера и соседним блокам. Рассчитано на честную
ошибку программиста (раздел 8 — что скрипт делать не должен и почему).

- Управляющий цикл скриптом не задерживается: скан ждёт ответ ограниченное время (`wait,us`, не больше 10 % такта
  за цикл), дальше скрипт досчитывается в фоне; исполнитель поток скана всегда вытесняет.
- Скрипт — в своём процессе (с 0.16.0): его вечный цикл, долгий вызов на C или аварийное завершение рантайм и
  соседние скрипты не задевают.
- Предел на вызов (`tlim,ms`/`per_call_ms`): дольше — прерывание, `result −16`; не помогло за 100 мс — процесс
  скрипта останавливается и при следующем вызове загружается заново; функция-«нарушитель» дальше идёт с
  пониженным приоритетом, пока не уложится; тревога «исполнитель занят». Загрузка скрипта — свой предел.
- Открытые файлы и соединения рантайма считаются раз в секунду: больше половины предела — тревога «много открытых
  файлов и соединений» (выход `alarm`, журнал).
- Память скрипта ограничена (с 0.16.0, `mem_mb`, 64 МБ): растущий без меры список или одно огромное выделение дают
  скрипту `MemoryError` (код `−6`), процесс скрипта жив, память рантайма не растёт; при нехватке памяти всего
  контроллера ядро убивает процесс скрипта, а не службы. Открытых файлов и соединений у процесса скрипта — не больше
  `max_files` (64).
- Строгие проверки на границе: номера, число аргументов, длина и вид результата — явными кодами; за пределы
  выходов блока запись невозможна; аргументы без утечки памяти.
- При ошибке выходы держат прежние значения или, если в скрипте объявлен `SAFE`, принимают безопасные (с 0.18.0,
  раздел 5.5) — контроллер берёт их из текста скрипта сам, даже когда скрипт завис и остановлен или не загрузился.
- Файл ошибки переписывается только при смене текста; каталог скриптов — в конце `sys.path`, байт-код не пишется;
  перевод огромных целых в строку ограничен 4300 цифрами.
- Операции, опасные для рантайма (процесс, потоки, запуск программ — раздел 8.5), **в блоке недоступны**:
  попытка прерывается кодом `−22`. Сеть, COM-порты и файлы — только по галочкам свойств блока; файлы — в папке
  скрипта (флеш и ОЗУ) с пределом объёма (раздел 8.8).
- Процесс скрипта изолирован (с 0.17.0): свой непривилегированный пользователь (не root — чужие файлы и службы
  контроллера не тронуть), без галочки «сеть» — сети нет совсем, общие на запись каталоги (`/tmp`) скрыты. Это
  дополняет проверку скрипта, а не заменяет её.

**Чего пока нет.** Нет жёсткой границы времени для вызова на C короче предела + 100 мс (до остановки процесса он
держит исполнителя — раздел 8.1). Память и число открытых файлов ограничены пределами процесса скрипта (`mem_mb`,
`max_files`); тем не менее скрипт должен укладываться во время (раздел 3.4) и бережно расходовать память.

## 10. Проверка скрипта на компьютере до загрузки

**Автоматически в диалоге блока.** Каждый раз, когда SMLogix разобрал новый текст скрипта без ошибок в
`INPUTS`/`OUTPUTS` (при открытии диалога со связанным файлом, после «Обзор…», ввода пути, возврата из редактора,
«Перечитать файл»), он сам проверяет скрипт на ПК — так же, как ручная проверка ниже, с пределом времени вызова
500 мс и всеми входами, равными 0.

- Всё в порядке или есть только замечания **ВНИМАНИЕ** — **ничего не показывает** (их видно только при ручной
  проверке).
- Есть **НЕЛЬЗЯ**, ошибка в `SAFE` (5.5) или ошибка при пробном вызове — **открывает `py.log`** с тем же текстом,
  что выдаёт ручная проверка; там же назван код `result`, которым ответит блок на контроллере.
- Это **только предупреждение: скрипт в блок всё равно принимается** — в диалоге «Загружено в проект…», красной
  надписи нет. Исправьте файл и нажмите «Перечитать файл» (без связи с файлом — выберите его заново); иначе с
  проектом на контроллер уйдёт скрипт с ошибкой.
- Ошибка в `INPUTS`/`OUTPUTS` устроена иначе (3.1): скрипт не принимается, в блоке остаётся прежний, а проверка на
  ПК не запускается.
- Проверка идёт фоном: если закрыть диалог раньше, чем она закончится, `py.log` не откроется.
- Для проверки нужен Python 3.13 на ПК; если его нет, SMLogix один раз предложит скачать и установить его сам
  (папка рядом с журналами, в систему ничего не ставится), а до тех пор проверку молча пропускает — скрипт всё
  равно проверит контроллер при загрузке проекта.

**Вручную** тем же `pyscript_check.py` (лежит рядом с SMLogix-PyScript). Он проверяет скрипт до загрузки в
контроллер (нужен Python 3.13 или новее на ПК, как на контроллере): объявление `INPUTS`/`OUTPUTS`, точку входа,
число аргументов, вид и длину результата (real = float32), словарь `SAFE` (5.5; при удаче печатает «при ошибке
(SAFE): HEAT = 0.0, …»), допустимость операций в блоке — и один раз вызывает точку входа с заданными аргументами.

```bash
python pyscript_check.py мой_скрипт.py 12.5 1
```

Каждое замечание — что найдено и вердикт простыми словами: **НЕЛЬЗЯ … — запрещено использовать** (или **— нет на
контроллере**; тогда на ПК скрипт не запускается — на контроллере блок ответил бы `−22`) и **ВНИМАНИЕ … — не имеет
смысла** (с короткой причиной) или с оговоркой. В конце в скобках — где подробности: «(раздел 8.5)» — раздел этого
файла, «(библиотеки, раздел 3)» — приложения `ЗНАНИЯ-PyScript-библиотеки.md`; скобок нет — отдельного раздела об
этом нет. Те же тексты контроллер пишет в `script<sid>.txt`. Предел времени вызова — `--tlim МС` (по умолчанию
1000). Код возврата: `0` — годен, `1` — ошибка (печатается код `result`, который покажет блок), `2` — ошибка
объявления.

Пример (скрипт обращается к сети и печатает):

```
объявление: execute() — входов 1, выходов 1
  НЕЛЬЗЯ строка 1: модуль socket — запрещено использовать (раздел 8.5)
  ВНИМАНИЕ строка 7: print() — не имеет смысла: вывод нигде не виден (раздел 8.5)
ОШИБКА: result -22: запрещённого в скрипте — 1; на контроллере скрипт не загрузится или вызов прервётся. На ПК не запускаю
```

Чего проверка не знает: скорость контроллера (оценка ×50…80, точно — `duration,us`), очередь с другими блоками,
состояние между вызовами (вызов один).

## 11. Правила для Claude

**Как говорить с человеком — главное.**

- Говори просто, без устройства PyScript. Для человека есть **SMLogix** (программа на компьютере) и
  **контроллер** — и всё. Не рассказывай, что внутри есть проверщик, рантайм, оболочка, исполнитель, белые
  списки, перехватчики и т. п.: ему это не нужно и не интересно. Пиши «SMLogix проверил скрипт», «контроллер
  прервёт вызов», а не названия внутренних частей.
- Спросили, **можно ли использовать** функцию или модуль, — отвечай одной фразой: «можно», «данная функция
  запрещена для использования» (для модуля — «данный модуль запрещён для использования»), «не имеет смысла» —
  с короткой причиной (`print` — вывод нигде не виден) или «этого модуля нет на контроллере». Подробности —
  только если спросят «почему», и тоже простыми словами. Сверяйся с приложением `ЗНАНИЯ-PyScript-библиотеки.md`
  и разделом 8.
- Спросили про **файлы, сеть или COM-порты** — «можно, если в свойствах блока включить галочку «Разрешить
  операции с файлами»» (или «… работу с сетью»); предупреди, что её включение — отказ от гарантийного
  обслуживания ПЛК, и что файлы — только в папке скрипта: до 4 МБ на флеше, до 64 КБ в `ram/` (раздел 8.8).
- В `py.log` и в `script<sid>.txt` замечание кончается номером раздела в скобках: «(раздел 8.5)» — этого файла,
  «(библиотеки, раздел 3)» — приложения. Это подсказка тебе, где подробности; человеку перескажи суть, а номер
  назови, только если он сам хочет почитать.

Когда пишешь или правишь скрипт PyScript:

1. Объявляй `INPUTS`/`OUTPUTS` словарями с начала строки, имена латиницей, типы `float/bool/int/'long'`,
   запятая после каждого элемента (и после последнего);
   точка входа — `def execute(...)` с начала строки, аргументы в порядке `INPUTS`; вспомогательные функции —
   не на `func…`.
2. Возвращай кортеж ровно из `len(OUTPUTS)` чисел в порядке `OUTPUTS`; `bool` — как `True/False` или 0/1;
   никогда `None`. Если выход управляет тем, что при ошибке должно перейти в безопасное состояние (нагрев, клапан,
   пуск), предложи человеку словарь `SAFE` (5.5): какие выходы и какие значения — решает он; без `SAFE` при ошибке
   выходы держат прежние значения.
3. Помни: аргументы — float32 в `float`; сравнения с допуском; индексы через `int()`; выходы — float32.
4. Импорты — наверху файла; только стандартная библиотека Python 3.13 (нет numpy, нет `ctypes`, `curses`,
   `readline` и модулей, удалённых в 3.8–3.13, — раздел 8.7; проверяй модуль и функцию по приложению
   `ЗНАНИЯ-PyScript-библиотеки.md`); синтаксис 3.13 доступен (`:=`, `match`, `f'{x=}'`, параметры `/`).
5. Не используй то, что ломает рантайм или недоступно в блоке: `subprocess`, `os.system/popen/fork/_exit/kill/chdir/umask`,
   `os.environ[...] =`, `multiprocessing`, `ctypes`, `signal`, `faulthandler`, изменения `sys.*`/`gc`/`resource`/
   `locale`, присваивание атрибутам модулей, `threading`, `input`, `time.sleep`; `print` для диагностики не имеет
   смысла — вывода не видно; не пиши `except:`/`except BaseException:` — только `except Exception:`.
6. Укладывайся во время: оцени цену по таблице 3.4; без `statistics` в горячем пути; без тяжёлых импортов
   внутри функции; длинный счёт — честно асинхронный (сообщи пользователю про `result = 3`, `tlim,ms`, `wait,us`,
   конвейер).
7. **Время в скрипте считай только по надёжной опоре** (раздел 8.9): по часам контроллера — `time.monotonic()`
   для промежутков, `time.time()`/`datetime` для календаря и меток — или по сигналу программы ПЛК, поданному на
   вход (прошедшее время, шаг, номер периода). Никогда не считай время числом вызовов и не жди внутри вызова
   (`time.sleep`): вызов асинхронный, промежутки неравные, переменные скрипта могут начаться заново. Согласование
   скриптов между собой (передача данных, очерёдность, взаимные блокировки), то, что должно сработать в каждом
   такте (защиты, блокировки), и надзор за ответом скрипта делает только программа ПЛК (FBD): скажи человеку,
   какие блоки поставить в FBD и что подать на входы скриптов.
8. Состояние — в глобальных переменных модуля; у каждого блока и у каждой копии оно своё.
9. Сеть, COM-порты и файлы — только если в свойствах блока включена галочка (раздел 8.8); иначе обмен с другими
   устройствами — средствами программы ПЛК. Нужна галочка — скажи человеку, какую включить, и предупреди об отказе
   от гарантии. Словарь `SECURITY` в скрипт сам не пиши — его пишет SMLogix по галочке. Любой путь к файлу —
   внутри папки скрипта; часто меняющееся — в `ram/…` (до 64 КБ, пропадает при выключении питания), на флеш — редко
   (до 4 МБ).
10. Проверь скрипт `pyscript_check.py` (раздел 10) с осмысленными аргументами; человеку скажи итог простыми
    словами («скрипт годен», «в строке 3 — запрещённая функция …»), вывод покажи, если он просит; модули сверяй
    по `ЗНАНИЯ-PyScript-библиотеки.md`.
11. Разбирая ошибку, проси у пользователя: код `result`, содержимое `/projects/py/script<sid>.txt`,
    `/run/pyexec.status`, строки `PyScript` из `/var/log/user.log`; номер `sid` — по имени файла с ошибкой.
    Ошибка в диалоге блока на ПК — проси `%LOCALAPPDATA%\SMLogix\py.log`.
12. Правку скрипта со связью с файлом Ctrl+Z в SMLogix не откатывает (3.1): прежний текст возвращай в самом
    файле.
13. Эти файлы знаний — для написания скриптов, не для доработки PyScript: не предлагай менять рантайм logix
    или оболочку SMLogix.

Когда работаешь с контроллером по SSH:

- Сначала убедись, что это тот контроллер: `cat /proc/sv` (модель, серийный номер) — сверь с пользователем.
- Только чтение, пока пользователь не разрешил иное: `cat`, `ls`, `grep`. Не перезапускай рантайм, не
  устанавливай/удаляй пакет, не правь файлы в `/projects` без явного согласия — это останов управления.
- Никогда не пиши в память процесса logix (`/proc/<pid>/mem`) и в его shmem.
- Загрузка проекта из SMLogix стирает `/root/.ssh` контроллера — ключ SSH после неё восстанавливает
  пользователь.
- Пароли не вводи и не храни; ключи — дело пользователя.

## 12. Термины и файлы

| термин | значение |
|---|---|
| logix | рантайм контроллера: исполняет программу FBD |
| скан, такт | один проход программы FBD (поток `Step`, реальное время) |
| исполнитель | поток `pyexec` внутри logix, где живёт интерпретатор Python |
| заявка | вызов скрипта, поставленный блоком в очередь исполнителя |
| `sid`, `fid` | номер скрипта (файл `script<sid>.py`) и точка входа (всегда 0 — `execute`) |
| `/projects/py/` | скрипты проекта, файлы ошибок, `pyexec.conf`, опись `names.txt` («номер — имя скрипта») |
| `/projects/pydata/<имя>/` | папка файлов скрипта (галочка «Разрешить операции с файлами»), до 4 МБ; для скрипта — корень путей |
| `/run/pydata/<имя>/` | папка скрипта в ОЗУ — путь `ram/…`, до 64 КБ, пропадает при выключении питания |
| связь с файлом | галочка «Сохранять связь с файлом» в диалоге блока: со связью скрипт берётся из файла на ПК, без — живёт только в блоке |
| `py.log` | журнал ошибок разбора и замечаний проверки скрипта в диалоге блока, `%LOCALAPPDATA%\SMLogix\py.log` (ПК) |
| `/run/pyexec.status` | состояние исполнителя (в памяти, раз в секунду) |
| `/var/log/user.log` | системный журнал рантайма |

Приложение: **`ЗНАНИЯ-PyScript-библиотеки.md`** — что ставит пакет; факты об интерпретаторе; сводная таблица

импорта и оценкой (✅ / ⚠ с оговоркой / ☑ с галочкой); их
функции, классы, исключения и константы — снято с контроллера на Python 3.13.16 (22.10.2026); C API TensorFlow
Lite 2.10.0 и libpython 3.13 — для полноты, скриптам недоступны. Если нужного модуля в приложении нет — в блоке
